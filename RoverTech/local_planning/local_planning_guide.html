Local Path Planning

The Local Planner (Controller) is the actual "Driver". It takes the mathematical blue line from the Global Planner and attempts to follow it, while dodging dynamic, immediate obstacles that the SLAM map doesn't know about yet.

How it works conceptually

  • It looks at the upcoming segment of the /plan waypoint path.
  • It reads the Local Costmap, which is a small window (e.g. 5m x 5m) around the rover that is constantly updated with real-time perception data (rocks that just rolled into view).
  • It calculates the rover's physical kinematics: "Can a skid-steer rover make a turn this sharp at 0.5 m/s?"
  • It generates a smooth curve (trajectory) that dodges the immediate rock while trying to merge back onto the Global Path.

Core ROS 2 Nodes

Handled by the nav2_controller server. Popular plugins include DWA (Dynamic Window Approach) or TEB (Timed Elastic Band), which are highly configurable for skid-steer or ackermann rovers.

Input & Output Flow

Inputs:

  • /plan: The global path to follow.
  • /perception/obstacles_only: Feeds the local costmap so it knows what to dodge right now.
  • /odometry/filtered: Current speed and momentum of the rover.

Outputs:

  • /cmd_vel (geometry_msgs/Twist): The exact velocity commands. e.g., Linear X = 0.5 m/s, Angular Z = 0.2 rad/s.
